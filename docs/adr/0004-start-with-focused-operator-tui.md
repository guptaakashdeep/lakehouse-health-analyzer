# Start with Focused Operator TUI

The first terminal interface will be a focused operator TUI rather than a chart-heavy dashboard clone. The default `lakehouse-health-operator` command should launch the interactive Textual TUI, with explicit subcommands reserved for setup and scriptable report export workflows. Textual and Rich should be required project dependencies because the default operator command depends on them, and the project will directly use Rich renderables and styles. It should let users inspect registered catalog tables, run or view headline health metrics for those tables, analyze a selected table, and export results, while richer visual exploration remains in the Streamlit dashboard for now. The TUI should be keyboard-first, with mouse support allowed where Textual provides it naturally. Initial key bindings should include arrow keys and `j`/`k` for movement, Enter for selection or analysis, `/` for search or filtering, `r` for refresh, `e` for export, `s` for setup or settings, and `q` for quit. Catalog navigation should discover available top-level catalog namespaces through the shared catalog access layer, label them as databases for Glue-facing users, and lazily list tables only when a namespace is selected. Hierarchical namespaces can be shown as flat fully-qualified namespace entries in the first version rather than as a nested tree. The table list panel should render each table with the table name left-aligned and a right-aligned table format label, using `ICEBERG` when the format is positively detected, `UNKNOWN` when it cannot be determined cheaply, and `NON-ICEBERG` after an attempted analysis proves the table is unsupported. Highlighting a table should not trigger full table analysis; full analysis should start only after explicit selection, such as pressing Enter. Selecting an `UNKNOWN` table should attempt Iceberg analysis, promote the format label to `ICEBERG` when analysis succeeds, and mark it `NON-ICEBERG` when the table remains unsupported. Selecting a cached `NON-ICEBERG` table should show an unsupported-table detail state with options to go back or refresh the status. After a table is analyzed, the detail panel should show maintenance recommendations first, grouped by severity, followed by calculation warnings and then grouped metrics. Detail sections should be ordered as recommendations, warnings, files, records, partitions, snapshots, metadata and evolution, and source and runtime. Metric rendering should use Rich/Textual styling and color to improve scanability, with color carrying severity, state, and freshness cues rather than decorative noise. The visual theme should use a modern, colorful, easy-on-the-eyes palette across panels, borders, focus states, and badges; critical should read as red, warning as amber or yellow, info as blue or cyan, healthy or success states as green, unknown or not-analyzed states as muted gray, and cached or stale values as a secondary accent color. Text labels such as `CRITICAL`, `UNKNOWN`, `CACHED`, and `NON-ICEBERG` should remain visible so the interface does not rely on color alone. Catalog overview should load table identities first, then fetch headline metrics concurrently with a configurable limit so slow or unavailable tables do not block the entire TUI; headline metrics should include file, partition, snapshot, expirable snapshot candidate, warning, and maintenance recommendation counts where available. The non-interactive report command should accept a namespace-qualified table identifier, use the configured catalog from setup, config file, environment, or flags, and split the identifier so the final segment is the table name and earlier segments are the catalog namespace. The report command should print JSON or Markdown to stdout by default for scriptability, and write files only when an explicit output path or configured output policy requests it. Expirable snapshot candidates should use a configurable retention policy with a 30-day default, excluding the current snapshot. Orphan-file details are intentionally out of scope for the first serious version.
